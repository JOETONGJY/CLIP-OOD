## 1. 研究背景

本毕设基于 CVPR 2025 论文 **LanCE（Language-guided Concept Erasing）**，主题为**域泛化下的可解释图像分类**。

- 在 CLIP 文本编码器上构建**概念瓶颈模型（CBM）**：把图像视觉特征映射到人类可理解的概念空间（如"有翅膀""红色喙"），再由概念预测类别。
- 域泛化目标：在 source 域（如真实照片）训练，在 target 域（如油画、剪贴画、素描、雕塑、3D 模型）测试时仍保持精度。
- 论文提出 **DDO（Domain Descriptor Orthogonality）正则化器**：用自然语言 prompt 描述域迁移方向，让分类器对该方向"不响应"（正交），从而抹除域相关概念、提升 OOD 泛化。

### DDO 原理（代码位置 `model/cbm_models.py` `clip_cbm_orth`）

1. source prompt 固定为 `a photo of a {}.`，target prompt 有 200 个变体（painting / clipart / sketch / sculpture / 3D … 及形容词修饰）。
2. 对每个 `(source, target)` prompt pair，对所有类别编码文本嵌入，做差并归一化得到**域迁移方向向量** `diffs`：
   - `raw_diffs = target_emb - source_emb`，形状 `(num_classes, feat_dim)`
   - `normed_diffs = raw_diffs / (raw_diffs.norm(dim=-1) + eps)`
3. 投影到概念空间：`domain_concept_projection = diffs @ concept_embeddings.T`，形状 `(num_prompts, num_classes, num_concepts)`。
4. 过分类器（LayerNorm+Linear）得到 `regularizer`，正则损失 `orth_loss = |regularizer|.mean()`。
5. 总损失：`L = cls_loss + α·orth_loss + β·concept_loss`。

## 2. 我的已有创新：Reliability-Weighted DDO

**动机**：原 DDO 对 200 个 prompt pair 一视同仁，但有些 prompt 描述的域迁移质量高、有些是噪声。

**已有做法**（`data/CUB/cub_data.py:92-118`）：

对每个 prompt pair，用**不同类别间 shift 方向的一致性**衡量可靠性：

```python
cos_sim = normed_diffs @ normed_diffs.T          # (num_classes, num_classes)
mask = ~torch.eye(num_classes, dtype=torch.bool)
reliability_score = cos_sim[mask].mean()          # 标量, 越大越"一致/可靠"
```

直觉：同一 prompt 在不同类别上产生的迁移方向越一致，说明它描述的域迁移越本质。

然后**二值化加权**：

```python
threshold = scores.median()
domain_weights = torch.where(scores >= threshold, HIGH, LOW)  # HIGH/LOW 手调
# 在 model 中: regularizer = regularizer * weights.view(-1,1,1)
```

实验中实际测试过多套手调值（截至本次梳理）：

| 数据集 / 变体 | HIGH | LOW | 代码位置 |
|---|---|---|---|
| `CUB` (`Processed_CUB_Dataset`) | 1.8 | 0.75 | `data/CUB/cub_data.py:114-118` |
| `CUB` (`Processed_CUB_Dataset_Labo`) | 1.5 | 0.5 | `data/CUB/cub_data.py:242-246` |
| `AWA2` (`Processed_awa2`) | 1.8 | 0.75 | `data/awa2/awa2_data.py:73-77` |
| `AWA2` (`Processed_awa2_Labo`) | 1.25 | 0.75 | `data/awa2/awa2_data.py:197-201` |

> **这一现象本身就是困境 B 的直接证据**：同一方法在 4 个变体上需要 3 套不同的手调值，说明"二值化 + 手调双值"这个范式不可泛化，应当被整体替换，而非寻找"通用的两套值"。

## 3. 当前困境（核心问题）

当前实现存在三个待解决的问题：

### 困境 A：二值化丢失信息
reliability_score 本是连续值（约 [-1,1]，实际多为正），median 二值化后只保留"高/低"两档，丢失了梯度信息。中位数附近的两条 prompt 差异极小却被分到两档，不合理。

### 困境 B：阈值与双值是手调超参数
`threshold=median` 和 `HIGH/LOW` 完全靠人工实验选择，换数据集（CUB→AWA2→LADA→LADV）很可能要重调，泛化性差，也不符合"自适应"的研究目标。

### 困境 C（最根本）：可靠性 ≠ 有效性
`reliability_score` 衡量的是**"迁移方向是否一致"**，但一致的方向**未必对泛化有益**：
- 一个 prompt 可能方向高度一致，但该方向与真实 target 域的迁移无关（例如 prompt "a blurry painting" 在所有类上一致地把图像推向"模糊"方向，但 target 域是"雕塑"，模糊方向对雕塑泛化无帮助甚至有害）。
- 真正该被放大的，是**"约束该 prompt 的正交性能实际提升 target 泛化"**的 prompt，而非仅仅"方向一致"的 prompt。

**这是当前可靠性度量无法触及的盲区**，也是自适应设计必须面对的核心矛盾。

## 4. 自适应权重候选方案

下面方案按"改动量从小到大 / 理论性由弱到强"排列。

### 方案 1：连续软加权（零超参，最简单）
直接用连续 reliability_score 构造权重，去掉阈值与双值：

```python
scores = torch.stack(weight_list).to(device)
# softmax 归一, 乘以 N 使均值为 1, 不改变 orth_loss 整体量级
self.domain_weights = torch.softmax(scores, dim=0) * len(scores)
```

- 优点：零超参，保留连续信息，自动强调高分 prompt。
- 缺点：仍完全依赖 reliability（不解决困境 C），softmax 可能过度集中。
- 改进：加温度 `softmax(scores/τ)`，τ 可固定或学习（见方案 2）。

### 方案 2：可学习温度
```python
# model 中: self.tau = nn.Parameter(torch.tensor(1.0))
weights = torch.softmax(scores / self.tau, dim=0) * num_prompts
```
单一可学习标量控制权重分布锐度，比手调双值更 principled。

### 方案 3（推荐）：可学习逐 prompt logits + 可靠性先验 + 熵正则
让每个 prompt 的权重成为**可学习参数**，用 reliability_score 作为**先验初始化**，端到端随分类损失学习：

```python
# model __init__:
self.domain_logits = nn.Parameter(scores.clone().detach())   # 先验 = 可靠性
# forward:
weights = torch.softmax(self.domain_logits, dim=0) * num_prompts
regularizer = regularizer * weights.view(-1,1,1)
# 熵正则(防止退化为"全压在一个prompt上"):
ent = -(weights * (weights+1e-8).log()).sum()
total_loss = cls_loss + α*orth_loss + β*concept_loss - λ*ent
```

- 优点：**自适应**（数据驱动学习哪些 prompt 有用）、**保留我已有创新作为先验**（不丢弃 reliability）、参数量小（仅 `num_prompts` 个标量）、可消融（先验 vs 无先验）。
- 对困境 C 的回应：因为权重随目标（分类/泛化）梯度学习，模型会自动降低"一致但无效"prompt 的权重。
- 风险：端到端学习可能过拟合 source（source 上正交约束越强未必 target 越好）；需要熵正则防止权重坍缩。

### 方案 4：可学习映射 score→weight（小 MLP）
学一个从 reliability_score 到 weight 的非线性映射：

```python
self.score_map = nn.Sequential(
    nn.Linear(1, 8), nn.ReLU(), nn.Linear(8, 1), nn.Sigmoid())
# w_i = score_map(score_i); 归一化使均值 1
```
- 优点：可学最优映射曲线，且**可解释**（能画出 reliability→weight 的学习曲线，写论文有图）。
- 与方案 3 区别：约束所有 score 相近的 prompt 权重相近（参数共享），抗过拟合。

### 方案 5（最 principled，最复杂）：元学习 / 双层优化
把 prompt 权重 `ω` 作为**元参数**，用**target 验证集损失**驱动 `ω` 的学习，模型参数 `θ` 用 source 训练损失驱动：

- 内层：`θ* = argmin_θ L_source_train(θ; ω)`
- 外层：`ω* = argmin_ω L_target_val(θ*(ω))`

实践中用一阶 MAML 近似或交替优化。

- 优点：**直接优化"哪些 prompt 的约束真正提升泛化"**，从根本上解决困境 C。
- 缺点：需 target 验证集（可从 target 划出一小部分，或用部分 target 作 dev），实现复杂，训练成本高。
- 适合作为论文的"进阶方法"或与方案 3 对比。

## 7. 我的倾向选择与退化分析（请专家重点确认此节）

> **更新**：专家已回复，确认采用 **Prior + Residual + KL 正则** 框架（本节以下内容已按专家建议修订）。

经过对方案 1–5 的对比，**我倾向采用方案 3 的改进版作为毕设主方法**，并在论文中与"无先验""纯 reliability 软加权（方案 1）""原 DDO（无加权）"做消融。理由与设计如下。

### 7.1 为什么不选方案 5（元学习）

- 现有训练循环（`main.py:194-227`）中 `source_test_loader` / `target_test_loader` 仅用于 evaluate，**没有 target 验证集损失驱动**的现成机制；从 target 划 dev set 会破坏 DG"测试时无 target 标签"的严格设定。
- 双层优化实现成本高、训练慢，毕设时间预算有限。
- 方案 3 改动小、可消融、可画权重学习曲线，性价比最高。

### 7.2 为什么不选方案 1（纯 reliability 软加权）

- 仍完全依赖 `reliability_score`，**没解决困境 C**（一致 ≠ 有效）。
- 没有"学习"成分，论文创新性不足，难以支撑毕设的工作量要求。

### 7.3 方案 3 改进版的具体设计

在 `model/cbm_models.py:clip_cbm_orth` 中：

```python
# __init__ 中（scores 来自数据集，已 detach，shape (num_prompts,)）
self.domain_logits = nn.Parameter(scores.clone().detach())   # 先验 = reliability

# forward 中
w = torch.softmax(self.domain_logits, dim=0) * num_prompts   # 均值=1, 保量级
w = w.clamp(min=0.3)                                          # 下界, 防坍缩
regularizer = regularizer * w.view(-1, 1, 1)

# loss 中（main.py）
ent = -(w * (w + 1e-8).log()).sum()
total_loss = cls_loss + α * orth_loss + β * concept_loss - λ * ent
```

### 7.4 关键设计点：为什么单靠熵正则不够，必须加下界 clip

针对第 5 节问题 3（防退化），我认为**熵正则方向不对**：

- 熵正则 `-λ·ent` 鼓励权重**分散**（熵大），但模型退化的真正风险是"把所有正交约束权重压到 0 以降低 source 训练损失"——熵正则反而可能加速这种坍缩（均匀的小值熵最大）。
- 真正的退化是"权重整体趋零"，应约束的是**权重的下界与量级**，而非分布形状。

因此我提议：

| 约束 | 作用 | 是否必要 |
|---|---|---|
| `softmax * N`（均值=1） | 保 `orth_loss` 量级，与原 DDO 可比 | 必须 |
| `clamp(min=0.3)` | 防止任一 prompt 权重学到 0（全关退化） | **必须**（替代/补充熵正则） |
| 熵正则 `-λ·ent` | 防止权重过度集中到单个 prompt | 可选，λ 小 |

> **核心论点**：下界 clip 比熵正则更直接对应退化风险。论文中可消融"有 clip / 无 clip / 有熵正则 / 无熵正则"四组，预期"有 clip"组 target acc 最稳定。

### 7.5 对困境 C 的回应（论文写作要点）

方案 3 让权重随 `cls_loss` 梯度学习，表面上是"source 驱动"，似乎没直接优化 target。但：

- `orth_loss` 约束的是分类器对域迁移方向的响应，**source 上分类损失 + 正交约束的联合优化本身就在塑造泛化方向**。
- reliability 先验提供"哪些 prompt 描述的迁移更本质"的归纳偏置，可学习 logits 在此基础上微调"哪些约束与当前分类任务相容"。
- 这比纯 reliability 更进一步，且不依赖 target，符合 DG 严格设定。

### 7.6 数据流改造点（实施时需改的文件）

1. `data/CUB/cub_data.py:92-118` 和 `219-246`：删除二值化，改为 `self.domain_weights = scores`（连续值，传给 model）。
2. `data/awa2/awa2_data.py:62-77` 和 `186-201`：同上。
3. `data/LAD_animal/lad_A_data.py`、`data/LAD_vehicle/lad_V_data.py`：同上（若已实现 reliability）。
4. `model/cbm_models.py:171-235`：`domain_weights` 改为 `domain_logits`（nn.Parameter），forward 中 softmax + clamp。
5. `main.py:163-169`：total_loss 加 `-λ·ent` 项（若用熵正则）。

## 9. 专家回复结论与最终实现方案

### 9.1 专家确认的方向

1. **方案 3（Prior + Residual）作为毕设主方法完全成立**，无需上方案 5（元学习）。
2. **否定 `clamp(min=0.3)`**：不可导、无理论依据、破坏 softmax 概率解释。改用 **KL 正则** 约束 residual 不偏离 uniform。
3. **关键改进**：reliability 不应直接作为可学习权重的初始化，而应定位为**先验（Prior）**。采用 `logits = prior + residual` 设计，residual 初始为 0，随训练学习修正。
4. **未来扩展**（时间允许）：融合多特征（方向一致性、语义多样性、文本相似度）+ 小 MLP 映射，把论文重点从"调权重"提升为"评价 prompt 质量"。

### 9.2 最终实现：Prior + Residual + KL 正则

**数学形式**：

```
prior = reliability_scores (detach, 不更新)
residual = nn.Parameter(zeros)  (初始 0, 随训练学习)

logits = prior + residual
weights = softmax(logits) * N          # 均值=1, 保量级

KL 正则 = log(N) - entropy(softmax(residual))
        = KL(softmax(residual) || uniform)

total_loss = cls_loss + α·orth_loss + β·concept_loss + λ_kl·KL
```

**直觉解释**：
- **训练初期**：residual=0，`weights = softmax(prior)*N`，等价于方案 1（软加权），reliability 先验主导。
- **训练后期**：residual 学习，weights 被数据驱动修正，但 KL 正则约束 residual 不能偏离 uniform 太远（防止退化到"全压一个 prompt"）。
- **reliability 的角色**：提供**归纳偏置（inductive bias）**，而非最终答案。论文中可清晰回答"为什么 reliability 有用"。

**与原方案 3 的区别**：

| | 原方案 3 | 专家建议（最终） |
|---|---|---|
| reliability 角色 | logits 初始值（训练后可能完全偏离） | prior（持续存在，detach） |
| 可学习部分 | 整个 logits | residual = logits - prior |
| 防退化机制 | clamp(min=0.3)（不可导） | KL 正则（连续可导，有概率解释） |
| 论文解释 | "初始化影响结果" | "reliability 是先验，residual 是数据驱动修正" |
