## 0. 三分钟速览

**任务**：域泛化（Domain Generalization）下的可解释图像分类。在"真实照片"上训练一个分类器，要求它在"油画 / 剪贴画 / 素描 / 雕塑"等**从未见过的风格**上依然分类准确，且决策过程人类可解释。

**基础**：CVPR 2025 论文 LanCE 的开源代码（本仓库 `CLIP-OOD-main` 就是它的 fork + 我们的修改）。LanCE 的核心叫 **DDO 正则化器**：用 204 个自然语言 prompt（"a painting of a {}"、"a sketch of a {}"...）描述"域会怎么变"，然后约束分类器对这些变化方向"没反应"（正交）。

**我们的两个创新点**（对应毕设论文第三、四章）：

| | 第三章：importance modeling | 第四章：structure modeling |
|---|---|---|
| 一句话 | 204 个 prompt 不该一视同仁，按"可靠性"加权，且权重可被数据修正 | 204 个 prompt 方向不独立，存在低维共享结构，把它压成一个子空间并"软抹除" |
| 核心机制 | Reliability Prior + 可学习 Residual + KL 正则 | SVD 自适应子空间 + 可学习抑制强度 γ + 不变分类头 |
| 代码入口 | `--CBM_type clip_cbm`（实际是 `clip_cbm_orth`）| `--CBM_type clip_cbm_subspace` |

**当前状态**：全部代码实现完毕，mock 数据 smoke test 通过，真实 CLIP 上跑完了 4 个免训练诊断分析（结果非常漂亮，直接可写进论文）。**卡在真实数据集下载**（CUB/AWA2/LADA/LADV，防火墙问题），拿到数据后按第 7 节的命令跑闸门实验即可。

## 1. 背景知识

### 1.1 CLIP 是什么

CLIP（OpenAI）是图文对齐的预训练模型，有两个编码器：

- **图像编码器** `encode_image(image)` → 一个 768 维向量（ViT-L/14），代表"这张图的内容"
- **文本编码器** `encode_text("a photo of a dog")` → 同样维度的向量

关键性质：**语义相近的图和文，向量方向相近**（余弦相似度高）。所以"图 ↔ 文本"可以互相检索、比对。

本项目 **CLIP 全程冻结**（`requires_grad=False`），只在它上面训练一个很小的分类头（几千个参数）。这既是 LanCE 的设定，也让训练极快、显存占用小。

### 1.2 概念瓶颈模型（CBM, Concept Bottleneck Model）

普通分类器：图像 → 直接输出类别（黑箱）。

CBM：图像 → **概念打分**（如"有翅膀 0.8、红色喙 0.2、生活在水上 0.9"）→ 由概念**线性**组合出类别。

好处：人类看得懂中间那一层，"为什么判成潜鸟？因为它有翅膀 + 水生 + ..."。这就是"可解释"。

在本代码里概念不需要人工标注，而是用 CLIP 文本编码器编码概念名（`cub_concepts.txt` 里有 112 个鸟类概念），然后：

```python
concept_activations = 图像特征 @ concept_embeddings.T   # (batch, num_concepts)
logits = classifier(concept_activations)                # LayerNorm + Linear
```

### 1.3 域泛化（Domain Generalization, DG）

- **source 域**：训练数据，如 CUB 的真实鸟类照片。
- **target 域**：测试数据，如 CUB-Painting（200 类鸟的油画版）。**训练时完全见不到 target 的任何图片**——这是 DG 的严格设定，区别于域自适应（DA 可以用无标签 target 数据）。

难点：模型容易学到"照片感"这类和类别无关、但和域强相关的特征，换到油画上就失灵。

### 1.4 本项目用的数据集

| 代号 | 数据集 | 类别数 | source | target |
|---|---|---|---|---|
| CUB | CUB-200 → CUB-Painting | 200 | 真实照片 | 油画 |
| AWA2 | AwA2 → AwA2-clipart | 50 | 真实照片 | 剪贴画 |

## 2. 原始方法 LanCE / DDO

我们的两个创新点都是对 DDO 的改进，必须先完全理解 DDO。

### 2.1 直觉

问：能不能**预先**告诉分类器"域会往哪些方向变"，让它对这些变化免疫？

LanCE 的答案：用语言描述域迁移。LLM 很容易生成上百种"图像风格"描述（painting, sketch, sculpture, ...），而 CLIP 文本编码器恰好能把它们变成向量。

### 2.2 具体流程（对应代码 `model/cbm_models.py` 的 `clip_cbm_orth`）

1. **构造 prompt pair**：source prompt 固定为 `"a photo of a {}."`，target prompt 有 **204 个变体**（`prompts/prompt200new.py`），如 `"a painting of a {}."`、`"a watercolor of a {}."`。

2. **算域迁移方向**：对每个 target prompt，把**全部 200 个类别**的类名代入 source/target prompt，各编码一次文本嵌入，做差归一化：

   ```
   diff_k = normalize( encode_text("a painting of a 麻雀") - encode_text("a photo of a 麻雀") )    # 对每个类 k
   ```

   得到 `domain_diffs`，形状 `(204 个prompt, 200 个类, 768 维)`。**直觉**：`diff` 就是"从照片变成油画"这个风格变化在 CLIP 空间里的方向，且它对每个类分别计算（同一个风格变化对不同类的推动方向略有不同）。

3. **投影到概念空间**：`domain_concept_projection = diffs @ concept_embeddings.T`，形状 `(204, 200, 112)`。即"这个风格变化会怎样篡改每个概念打分"。

4. **过分类器**：`regularizer = classifier[1:](domain_concept_projection)`，得到"如果输入沿域方向移动，分类器的输出会怎么变"。

5. **正交损失**：`orth_loss = |regularizer|.mean()`。**最小化它 = 让分类器对任何域方向的输入变化都不产生输出变化 = "正交/不响应" = 概念抹除（concept erasing）**。

   一个直觉例子："变成油画"这个方向可能会让概念"笔触可见""色彩鲜艳"的打分上升、"真实照片质感"下降——DDO 要求不管输入怎么沿这些方向移动，分类输出都纹丝不动，即**判断"是不是麻雀"只看翅膀/喙这些类别相关概念，不看笔触**。

6. **总损失**：`L = cls_loss + α·orth_loss + β·concept_loss`（α 默认 1，β 默认 0 因为这些数据集没有概念标注）。

### 2.3 DDO 的问题（我们改进的出发点）

204 个 prompt **一视同仁**（等权进入 orth_loss）。但显然有的 prompt 描述的域迁移"质量高"，有的是噪声。这就引出创新点一。

## 4. 创新点一（第三章）：Reliability-Weighted DDO

### 4.1 动机：DDO 的三个困境

这一段也是论文第三章"引言"的素材：

- **困境 A（二值化丢信息）**：最初的改进尝试是把 prompt 分成"可靠/不可靠"两档、分别乘手调的高/低权重。举个具体例子：两条 prompt 的 reliability 分别是 0.581 和 0.583，中位数是 0.582——仅仅因为跨过了中位线，权重就从 0.75 跳到 1.8，**2.4 倍的差别来自 0.002 的分数差**，明显不合理。
- **困境 B（手调不泛化）**：那个二值方案在 4 个数据集变体上用了 **3 套不同的手调值**（1.8/0.75、1.5/0.5、1.25/0.75）。这本身就是"范式不可泛化"的证据——我们的卖点恰恰是"自适应"。
- **困境 C（最根本：可靠性 ≠ 有效性）**：如何衡量一个 prompt 好不好？我们用"类间迁移方向一致性"（见 4.2）。但**方向一致 ≠ 对泛化有益**——一个 prompt 可能方向高度一致，却和真实 target 域的迁移无关（比如 "a blurry painting" 一致地把所有图推向"模糊"方向，但 target 域是雕塑，模糊方向没用甚至有害）。**真正该放大的，是"约束它能实际提升 target 泛化"的 prompt。**

### 4.2 核心概念：reliability 分数

**定义**（`reliability.py:34-97` `compute_domain_diffs_and_scores`）：

对每个 prompt（如 "a painting of a {}"）：
1. 对全部 K 个类，分别算归一化的迁移方向 `diff_k`（见 2.2 节第 2 步），得到 K 个单位向量；
2. 算这 K 个向量两两之间的平均余弦相似度（去掉对角线自己和自己）：

```python
cos_sim = normed_diffs @ normed_diffs.T          # (K, K)
mask = ~torch.eye(K, dtype=torch.bool)
reliability = cos_sim[mask].mean()               # 标量 ∈ 约[0,1]
```

**直觉**：如果"照片→油画"这个变化对麻雀、对老鹰、对鸭子……推动的方向全都差不多（一致性高），说明这个 prompt 描述的是一个**本质的、和类别无关的风格轴**——它可靠。反之，如果各类被推得东倒西歪，这个 prompt 就是噪声。

**一个具体例子**（假设只有 3 个类：麻雀、老鹰、鸭子）：

| prompt | 三个类各自的迁移方向 | 两两余弦 | reliability |
|---|---|---|---|
| "a watercolor of a {}" | 三个类都被推向同一个"水彩风"方向 | ≈ 0.8 | **≈ 0.8（高）** |
| "a constellation resembling a {}" | 麻雀被推向"星空图案"、老鹰被推向"星座神话"、鸭子被推向"天鹅座联想"——三个完全不同的方向 | ≈ 0.1 | **≈ 0.1（低）** |

"变成水彩"对任何鸟都是往同一个方向变，所以可靠；"长得像星座"对每个类的意义完全不同，所以是噪声。

**实证**（用真实 CLIP + 真实类名算过，`logs/domain_structure/*/reliability_top_bottom.txt`）：
- Top-10（最可靠）：watercolor / gouache painting / pencil drawing / silhouette / collage……全是**经典视觉媒介**；
- Bottom-10（最不可靠）：visual novel character / constellation resembling / album cover / anime style……全是**比喻、类别依赖**的描述。
- 且 CUB 和 AWA2 两个完全不同的类别集合给出的 Top/Bottom 语义高度一致 → 该指标捕获的是 prompt 本身的性质，有跨数据集稳定性。

### 4.3 最终方案：Prior + Residual + KL 正则

#### 4.3.1 设计哲学

reliability 分数不该是"最终答案"，而该是"**归纳偏置（先验）**"：

- 它回答的是"这个 prompt 描述的迁移方向是否**稳定**"（困境 C 前半）；
- 但"该给多大权重"应由**数据**回答——权重随分类损失的反向传播自动修正，模型会自己学会降低"一致但无效"prompt 的权重（困境 C 后半的回应）。

于是：**logits = prior + residual**，prior 是冻结的 reliability，residual 从 0 开始学习。

#### 4.3.2 完整数学形式

```
prior    = reliability_scores        （detach buffer，梯度流不到，永不更新）
residual = 0 初始化的可学习向量        （nn.Parameter，形状 (204,)）

logits  = prior + residual
weights = softmax(logits) × 204       （均值=1，保持 orth_loss 整体量级与原 DDO 可比）

KL 正则 = log(204) − H( softmax(residual) )  =  D_KL( softmax(residual) ‖ uniform )

total_loss = cls_loss + α·orth_loss + β·concept_loss + λ_kl·KL     （α=1，λ_kl=0.01）
```

**用一个 3-prompt 的迷你例子手算一遍**（真实是 204 个，原理相同）：

```
设 reliability scores = [0.62, 0.50, 0.30]      （依次是 watercolor / oil painting / album cover）

初始（residual = 0）:
  logits = prior = [0.62, 0.50, 0.30]
  softmax(logits) ≈ [0.40, 0.35, 0.24]          → weights = ×3 ≈ [1.19, 1.06, 0.73]
  可靠的 watercolor 初始权重高、不可靠的 album cover 低，且平均恰好 = 1。

训练若干 epoch 后（假设数据发现"约束 oil painting 收益其实最大、album cover 无益"）:
  residual 学到 [+0.1, +0.9, −0.8]
  logits = [0.72, 1.40, −0.50] → softmax ≈ [0.34, 0.68, 0.06] → weights ≈ [1.03, 2.05, 0.19]
  oil painting 被显著上调、album cover 被压低——这就是"数据驱动修正"。

（数字为示意；真实训练中每个 epoch 的 residual 都会存进 logs/weights/，可以画出这条演化曲线）
```

逐项解释：

| 组件 | 为什么存在 |
|---|---|
| `softmax × N` | softmax 后均值是 1/N，乘回 N 使权重平均值为 1——不加这个，加权会整体缩小 orth_loss，和原 DDO 不可比 |
| `residual` 初始 0 | **训练初期 weights = softmax(prior)×N，精确等价于"纯软加权"**。整个方法是从软加权平滑启动、被数据逐渐修正的 |
| KL 正则 | 防退化，详见下方专项解释。**初始时 residual=0 ⇒ softmax=uniform ⇒ KL 精确等于 0**（smoke test 验证过的事实） |
| λ_kl=0.01 | 小值，只防坍缩不主导。敏感性消融留了 {0, 0.001, 0.01, 0.1} 一组 |

**KL 到底防的是什么退化（专项解释）**：

`softmax × N` 保证权重均值恒为 1，所以"所有权重一起压到 0"在这套公式下不可能发生。真正的作弊路径是**过度集中**——模型可能发现某个方向特别容易"正交化"，就把它的权重推到 3.0、其余 203 个全压到 0.85：表面均值还是 1，但实际只约束了 1 个域方向，204 个方向的信息丢了 203 个。

KL 项盯着的正是这个：`softmax(residual)` 一旦开始"拉开差距"（这正是权重集中的前兆），KL 立即变大，以 λ_kl 的力度把 residual 拉回"各分量接近相等"的状态——等价于把最终权重拉回 prior 附近。它是连续可导的，且有清晰的概率解释（q 到均匀分布的距离）。

**被否决的替代方案**（论文里要能说清为什么不用）：
- ~~`clamp(min=0.3)` 下界裁剪~~：不可导、无理论依据、破坏 softmax 的概率解释。KL 正则是它的连续可导替代。
- ~~熵正则（鼓励权重分散）~~：方向就不对——退化风险是"权重过度集中/坍缩"（量级问题），不是"分布形状"问题。均匀的小值熵反而是最大的。
- ~~元学习/双层优化~~（用 target 验证集驱动权重学习）：理论上最 principled，但 (a) DG 严格设定下没有 target 标签可用；(b) 实现复杂训练慢；(c) 毕设时间预算不够。留作 future work。

#### 4.3.3 "先验不被训练污染"的四层解耦（论文可写的机制论述）

1. **梯度解耦**：prior 是 `register_buffer` + detach，optimizer 根本看不见它；
2. **时间解耦**：reliability 在数据集初始化时离线算一次（纯文本编码，不依赖训练），residual 在线学习；
3. **接口解耦**：reliability 模块只输出数值向量，模型不关心它的来源——将来换成多特征融合分数也不用改模型；
4. **概念解耦**：prior 回答"方向是否稳定"，residual 回答"当前任务需要多大权重"——正交的两个问题。

另外一个隐藏福利：AdamW 的 weight_decay 会持续把 residual 往 0 拉（= 往先验拉），相当于隐式的"先验信任"偏置。

```python
def __init__(self, ..., domain_weights=None, weight_mode="prior_residual"):
    if domain_weights is None or weight_mode == "none":
        self.reliability_prior, self.domain_residual = None, None     # 原 DDO 基线
    elif weight_mode == "fixed":
        self.fixed_weights = softmax(scores) * N                      # 纯软加权（buffer）
    else:  # "residual" 或 "prior_residual"
        if weight_mode == "residual":
            scores = torch.zeros_like(scores)                         # 无先验消融：prior 置零
        self.register_buffer('reliability_prior', scores.detach())    # 先验：梯度不可达
        self.domain_residual = nn.Parameter(torch.zeros_like(scores)) # 残差：从零学

def get_domain_weights(self):
    logits = self.reliability_prior + self.domain_residual
    weights = softmax(logits) * self.num_prompts      # 均值=1
    return weights, softmax(self.domain_residual)     # 第二个返回值给 KL 正则用

def forward(self, images):
    ...
    regularizer = self.classifier[1:](self.domain_concept_projection)
    weights, _ = self.get_domain_weights()
    if weights is not None:
        regularizer = regularizer * weights.view(-1, 1, 1)    # 逐 prompt 加权注入
    return concept_activations, self.classifier(concept_activations), regularizer
```

性能注意：`domain_concept_projection`（diffs @ concept_embeddings.T）在 `__init__` 算好缓存，forward 里只过分类器——原实现每次 forward 重算，慢 25 倍（代码里有注释标记）。

## 5. 创新点二（第四章）：Domain Subspace 不变分类

### 5.1 核心命题（一句话）

> **Domain prompts are not independent directions, but exhibit a shared and transferable low-dimensional structure.**

三、四章的关系（论文定位，表述已冻结）：
- 第三章 = **importance modeling**（哪些 prompt 重要 → importance-aware suppression）
- 第四章 = **structure modeling**（prompt 们怎么组织 → structure-aware suppression）
- 互补性证据：corr(reconstruction, reliability) ≈ **0.37**——相关但不等价，所以值得分别建模（这就是 2×2 联合实验的动机）。

### 5.2 动机：两个免训练诊断（先让数据说话，再设计方法）

我们的设计流程是"**先做诊断再写代码**"。诊断只需类名 + 204 prompt + CLIP 文本编码器，**不需要图片数据集**——所以它们已经用真实 CLIP 跑完了（脚本 `domain_structure_diagnosis.py`，结果在 `logs/domain_structure/`）。

**诊断 A：204×204 prompt 方向余弦矩阵**

把每个 prompt 的"类平均迁移方向"当作它的表示，算两两余弦：

| 统计量 | CUB | AWA2 |
|---|---|---|
| 平均 cos | **0.331** | **0.342** |
| 最大 cos | **0.987** | 0.982 |
| cos>0.7 的对占比 | 0.9% | 0.7% |
| 最相似对 | "a linocut of {}" / "a linocut print of {}" | 同 |

解读：平均 0.33 显著非零 → **prompt 们不独立，有共享结构**；最大 0.99（linocut 和 linocut print 几乎是同一条方向）→ 存在明显语义冗余对；跨数据集高度一致 → 结构是 CLIP 空间的固有属性。

**诊断 B：SVD 低秩性**

对 (204, 768) 方向矩阵做 SVD：

| 指标 | CUB | AWA2 |
|---|---|---|
| 前 5 维解释能量 EV(5) | 49.4% | 49.0% |
| 保 80% 能量所需维数 m | **32** | **34** |
| 保 92% 能量 | 68 | 72 |

解读：204 个方向其实活在一个低维子空间里；**同一个阈值 τ=0.8 在两个类别集合上自动给出几乎相同的维数（32 vs 34）** → 支持"用能量阈值自适应选维"而非写死维数。

### 5.3 方法链（四步，术语已冻结）

**Domain Structure Discovery → Adaptive Subspace Construction → Soft Domain Suppression → Invariant Classification**

```
① 结构发现      D ∈ R^{204×768}：每个 prompt 的类平均归一化方向，SVD: D = UΣVᵀ

② 自适应子空间  累计能量 CE(m) = Σ_{i≤m}σᵢ² / Σσᵢ²
                m(τ) = min{ m : CE(m) ≥ τ }        ← τ=0.8 默认，不写死维数
                B = [v₁,...,v_m]，投影矩阵 P_D = BBᵀ

③ 软抑制        z_inv = (I − γP_D)z，γ = σ(a) ∈ (0,1) 可学习标量
                （hardproj 是 γ≡1 的特例；γ≡0 退化为不投影——统一公式）

④ 不变分类      训练: L = CE(h_o(z)) + λ_inv·CE(h_inv(z_inv)) + α·L_DDO
                测试: 只用 ĥ = h_inv(z_inv)         ← 不做 ensemble，避免质疑
```

**两个手算例子**（帮你看懂 ② 和 ③）：

- **m(τ) 怎么算**（CUB 真实数字）：SVD 后把奇异值平方从大到小排序累加——前 5 个方向占 49.4% 能量，前 32 个恰好占到 80.0%。所以 τ=0.8 ⇒ m=32：**用 32 维的基替代表 204 个 prompt 方向，只丢 20% 能量**。AWA2 上同一个 τ 自动给出 m=34，几乎相同——这就是"自适应"的价值：不用为每个数据集手调维数，也不会因为类别数变了就失效。
- **γ 是什么**：把图像特征 z 拆成两部分——落在域子空间里的分量 z_D（大致对应"这是油画/照片/雕塑"的风格信息）和其余分量。z_inv = z − γ·z_D：γ=1 全删，γ=0 不删，γ 学到 0.7 就是"删 70% 留 30%"。初始 σ(0)=0.5（先删一半看看），之后由梯度决定——抹除有助泛化 → γ 变大；抹掉了类别信息 → γ 变小。训练日志每 epoch 打印 γ，它本身就是论文里的机制证据。

关键设计决策（每条都有明确的取舍理由）：

| 决策 | 理由 |
|---|---|
| 子空间 B 只从**文本**算出，不用任何 target 图片 | 符合 DG 严格设定（测试时无 target） |
| **软**抑制 γ=σ(a) 可学习，而非硬投影 | 主方向可能携带类别信息，完全擦除（γ=1）可能过强；γ 学出来是多少是重要的机制证据 |
| 投影位置在 **CLIP image embedding 层** | z → z_inv → concept bottleneck → 头。概念瓶颈依然可解释 |
| 双头：原始头 h_o 辅助 + 不变头 h_inv 主输出 | 测试只用 h_inv。h_o 的作用见 5.5 的诚实记录 |
| DDO 等权正则**保留** | 与第三章基线可比；第四章是叠加在 DDO 之上的模块 |

### 5.5 关键修正：DDO 作用对象（重要！）

**问题**（实现自查时发现，且比表面更严重）：原实现 `regularizer = classifier[1:](proj)` 只约束 original head，而测试用的是 inv_classifier。在 CLIP 冻结的 CBM 里**两个头没有任何共享参数**（γ 只在 z_inv 路径上）——即 original head 的全部梯度都不流向测试路径，**DDO 对测试头形同虚设**。

**修正**：两头都约束，`--eta_ddo_inv`（默认 1.0，对称）：

```python
regularizer = classifier[1:](proj) + eta_ddo_inv * inv_classifier[1:](proj)
```

单头模式（ddo/hardproj/softproj）唯一头即测试头，本来就一致。

**论文必须诚实记录**：frozen-CLIP 设定下 original head 的角色是 (a) headonly 消融的结构基础 (b) 无投影参照分类器（其 source acc 与 inv head 对比 = "投影代价"分析素材），**不是**传统意义上的"辅助监督防止表示被破坏"（该机制在表示不可学习时不成立）。论文里应把它写成 *training–inference alignment（实现一致性设计）*，不包装成创新点。

5. **Prompt reconstruction 分析**：explained ratio r_i = ‖Bᵀd_i‖²/‖d_i‖²——直观上就是把某条 prompt 的方向 d_i 投到子空间 B 上，看能量保留比例（watercolor 这类经典方向几乎被完全表达；carved pumpkin、astrological chart 这类异质描述表达明显差）。mean r 精确等于 τ（0.8→0.803）；**corr(r_i, reliability_i) = 0.37** → 三、四章互补性的核心证据。
6. **PC 语义轴**（`pc_loading_analysis.py`）：前 5 个主方向的 top-loading prompts 有清晰语义——PC1 插画/绘图轴（EV 34.5%）、PC2 3D结构化 vs 复古印刷、PC3 雕塑 vs 图解、PC4 绘画风格、PC5 海报/印刷。AWA2 的 PC4/PC5 与 CUB 几乎完全一致 → **SVD 基是语义可解释且跨数据集稳定的"域类型轴"**。

## 9. 已知的坑与注意事项

### 9.1 命名陷阱（最容易懵的地方）

- CLI 的 `--CBM_type clip_cbm` **实际映射到 `clip_cbm_orth` 类**（带 DDO + 权重机制的模型），不是文件里那个朴素 `clip_cbm` 类。映射在 `main.py:68-72` 的 `model_factory`。
- `--CBM_type cliplp` → `clip_mlp`（原论文的线性头基线，无 DDO）。
- "mode" 有两个不同维度：`--weight_mode` 是**第三章**的四组消融；`--ch4_mode` 是**第四章**的五组消融。两者独立。

### 9.2 数据侧 vs 模型侧的权重策略

- 数据集文件里的 `weight_strategy="prior_residual"` 是**硬编码**的，语义只是"把原始 reliability 分数透传给模型"，**做消融时不要改它**。
- 所有消融通过命令行 `--weight_mode` 在**模型侧**切换（模型会自行决定把 prior 置零/固定/学习）。
- `训练部署指南.md` 第六节"切换时改数据集文件里的 weight_strategy"是过时说明，以本文档 4.5 节为准。

### 9.3 已修复的原代码 bug（别再踩）

| bug | 修复 |
|---|---|
| `args.py` `batch_size` 是 `type=str` | 改 `type=int`（命令行传参报错） |
| `args.py` `epochs` 是 `type=float` | 改 `type=int`（`range()` 报 TypeError） |
| numpy 2.x 与旧 matplotlib 不兼容 | matplotlib 升级 3.8+ |
| forward 里每次重算 `diffs @ concept_embeddings.T` | 缓存为 `domain_concept_projection`（快 25 倍） |
| 第四章 DDO 只约束 original head（逻辑断裂） | 两头都约束，`--eta_ddo_inv 1.0`（见 5.5） |

### 9.4 行为上"看起来怪但其实对"的现象

- **KL loss 初始为 0.0000**：residual=0 时 softmax=uniform，数学上就该是 0。训练中随 residual 学习才增长。
- **residual 学得很慢**（2 epoch 只动 0.002）：mock 上无信号属正常。真实数据上若 100 epoch 后 Δw 仍极小，先查 λ_kl（默认 0.01 的拉力）再考虑调大 lr——这是设计阶段就登记过的"潜在失效模式"，已有对应分析预案（H(q) 曲线 + Δw 日志）。
- **mock 数据精度≈随机**：图片是噪声，只验证流程不验证效果。
- `--CBM_type clip_cbm_subspace` 时若不加 `--use_c3_weights`，`--weight_mode` 参数被忽略（强制 none），这是设计行为。
- 权重诊断日志只在**有 domain_weights 的模式**下输出（none 模式没有 `[Weights]` 行，只有 `[Ch4] gamma=` 行）。

### 9.5 环境/网络

- CLIP 权重下载是内网最大坑，实测有效流程（modelscope → 转格式 → patch 校验）在 `训练部署指南.md` 9.6 节，notebook 环境的权重已就位。
- wandb 是 offline 模式（`main.py` 里强制 `WANDB_MODE=offline`），结果在 `wandb/` 目录。
- 数据集是当前唯一 blocking，路径：外网下载 → 共享盘 → 训练容器，**不需要改任何代码**。

## 10. 论文写作要点

已冻结的表述规范（**必须遵守**）：

1. **跨数据集结果**写 "**strong cross-dataset consistency**" 或 "**dataset-insensitive tendency**"，**不写** "dataset-independent"（只验证了两个类别集合，不能过度声明）。
2. **corr(r_i, reliability_i)≈0.37** 是三、四章互补性的核心证据，固定表述："importance modeling 与 structure modeling 具有相关性，但明显不等价，因此分别建模具有合理性"。
3. DDO 双头约束写成 **training–inference alignment（实现一致性设计）**，不包装成创新点："为保证域正交约束直接作用于最终推理分支，本文同时对原始分类头和不变分类头施加 DDO 约束"。
4. 第四章术语链冻结：**Domain Structure Discovery → Adaptive Subspace Construction → Soft Domain Suppression → Invariant Classification**。
5. 评价协议：主表报 **best target acc**（当前实现），多 seed 报 mean±std，3 seeds。
6. 判定规则和闸门实验在真实数据前"写死"（见 5.6 / 7.2），**先定判据再看结果**，防"看结果改故事"。

论文可用素材清单（全部已产出）：`logs/domain_structure/` 下的 cosine 热图、SVD 谱图、reconstruction 分析图、PC loading 分析、跨数据集几何报告 + `专家咨询-论文第四章与实验规划.md` 第 8 节的数字表。

## 11. 术语表

| 术语 | 含义 |
|---|---|
| CLIP | OpenAI 图文对齐预训练模型，本项目全程冻结，只用它的两个编码器 |
| CBM | 概念瓶颈模型：图像→概念打分→类别，中间层人类可读 |
| DG / OOD | 域泛化 / 分布外。训练只见 source（照片），测试在 target（油画等） |
| DDO | LanCE 的正则化器：让分类器对语言描述的域迁移方向"不响应" |
| prompt | 域描述模板，如 "a painting of a {}."，共 204 个 target 变体 |
| domain_diffs | (204, 类数, 768)：每个 prompt 对每个类的归一化迁移方向 |
| reliability | 每个 prompt 的类间方向一致性得分（我们定义的质量度量） |
| prior | 冻结的 reliability 分数，作为权重的先验/归纳偏置 |
| residual | 可学习修正项，初始 0，logits = prior + residual |
| KL 正则 | D_KL(softmax(residual) ‖ uniform)，防权重坍缩 |
| orth_loss | DDO 正交损失，\|classifier(域方向投影)\| 的均值 |
| subspace / B | 204 个 prompt 方向 SVD 后的前 m 维基，m=m(τ) 自适应 |
| γ (gamma) | 软抑制强度，σ(a) 可学习，z_inv = z − γ·BBᵀz |
| invariant head | 测试专用的分类头，输入被抑制后的 z_inv |
| τ | 能量阈值（默认 0.8），决定子空间维数 m |
| 闸门实验 | 小规模先行实验，基本关系不成立就不铺开全量 |
| Δw | 最终权重 − 先验权重，数据修正方向的度量（机制分析核心量） |
| C3 / C4 | 论文第三章 / 第四章方法的代号（CLI 的 `--use_c3_weights` 即此意） |
